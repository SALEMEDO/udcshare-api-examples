# Contribution Guide

Merci de votre intérêt pour contribuer aux projets exemples UDCShare !

## 🤝 Comment contribuer

### Signaler des bugs

1. Vérifiez que le bug n'a pas déjà été signalé
2. Créez une nouvelle issue avec :
   - Titre descriptif
   - Description détaillée du bug
   - Steps to reproduce
   - Comportement attendu
   - Environnement (OS, version du langage/framework)

### Proposer des améliorations

1. Vérifiez qu'une amélioration similaire n'existe pas déjà
2. Créez une nouvelle issue avec :
   - Description de l'amélioration
   - Cas d'usage
   - Solutions proposées (si applicable)

### Soumettre du code

1. Fork le projet
2. Créez une branche pour votre feature (`git checkout -b feature/ma-feature`)
3. Commit vos changes (`git commit -m 'Add ma feature'`)
4. Push vers la branche (`git push origin feature/ma-feature`)
5. Créez une Pull Request

## 📝 Standards de code

### Python
- Suivre PEP 8
- Utiliser type hints
- Écrire des tests avec unittest
- Commenter le code complexe

### Node.js
- Suivre ESLint
- Utiliser async/await
- Écrire des tests avec Jest
- Documenter avec JSDoc

### JavaScript
- ES6+ features
- JSDoc comments
- Tests avec Jest
- Compatible tous navigateurs modernes

### PHP
- PSR-12 coding standards
- PHPDoc comments
- Tests avec PHPUnit
- Compatible PHP 8.0+

### Go
- Standard Go conventions
- godoc comments
- Tests avec go test
- Error handling explicite

### Ruby
- Ruby style guide
- RSpec tests
- YARD comments
- Compatible Ruby 2.7+

### React
- React best practices
- TypeScript recommended
- React Testing Library
- Husky hooks pour pre-commit

### Vue.js
- Vue 3 Composition API
- TypeScript recommended
- Vitest tests
- ESLint + Prettier

### Angular
- Angular style guide
- TypeScript strict mode
- Jasmine/Karma tests
- Angular CLI conventions

## 🧪 Tests

Chaque contribution doit inclure des tests :
- Tests unitaires pour les nouvelles fonctions
- Tests d'intégration si applicable
- Couverture de code > 80%

## 📖 Documentation

Toutes les contributions doivent inclure :
- Mise à jour du README si nécessaire
- Comments inline pour le code complexe
- Exemples d'utilisation pour les nouvelles features
- Mise à jour de la CHANGELOG

## 🔒 Sécurité

Pour les vulnérabilités de sécurité :
- Ne pas créer d'issue publique
- Envoyer un email à security@udcshare.com
- Attendre confirmation avant disclosure
